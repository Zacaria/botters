## Acceptance and decisions (before implementation)

- Both doctrine writers must inspect the existing `/profile` result. Only `{ok:true}` confirms the exact submitted revision; failure never means saved or received by an agent. Server acknowledgement is not proof of LLM execution.
- Preserve the live, unacknowledged draft on blur, actual lobby polls, menu transitions and in-match details close/reopen. Share the current draft between the two existing fields in this tab, not in storage. A later edit invalidates earlier success/failure notifications. Requests must not reorder writes of different revisions.
- Keep the lobby's 500 ms debounce. After failure, offer an ordinary keyboard-accessible retry button in the lobby and reuse the in-match send button. No automatic network retry, persistent queue, form framework or dependency. New edits still autosave normally in the lobby.
- Reuse `api`, the existing polling cadence, native fields/details/buttons and status/toast mechanisms. Retain HTML maxlength 500 and the existing server trim/slice(0,500) normalization. A stale GET started before an edit/acknowledgement must not rehydrate old text either.
- Draft lifetime is the living tab/session only. Reload, closing the tab, multi-tab conflict resolution and offline persistence are deliberately not covered. Session changes must not carry a previous session's draft or queued writes forward.
- Do not change name editing, transport, backend, authentication, simulation, tutorial, keyboard shortcuts, preferences, native assets, guide/installation work or providers. Do not create extra sessions/matches to retry.
