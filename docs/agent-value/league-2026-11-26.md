# Claude league against the house (2026-11-26)

**Verdict:** Normal was too hard. Claude Sonnet won 6/6 against Easy, 2/9 against Normal (`blob`) and 2/5 against Hard (`pincer`). A first fix (`flanker`) measured 1/5 live, no better. Normal is now `wary`: `flanker` that falls back from a battalion 1.5× its size. Live, Claude then won 3/5 against Normal (60 %).

## How it was played

- 20 valid matches on production (`play.botters.havesomecode.io`), 3 minutes and 17 planets each. Claude Code (`sonnet`) used the remote OAuth MCP connector with two QA accounts. One prompt per match: `start_match` at the given level, play alone to the end, one style (aggressive, defensive or economic).
- Claude only edited gambits (`set_gambits`, `toggle_gambit`); hand orders stay human-only. A browser signed in as the same account recorded the player's view.
- Two matches were voided and replaced (m21, m22). In m02 another worker's script surrendered on the shared QA account at 62 s. m05 never started: the agent saw both accounts' connectors and the tool permission blocked the call. Every later match loads only its own connector (`--strict-mcp-config`).
- About 1.1 $ of model usage and 65 turns per match (median). Raw rows: `league-2026-11-26/matches.json`. Gambit timelines: `league-2026-11-26/timelines.json`.

## First fix: offline replay

The 20 recorded gambit timelines (each edit at the game second it landed) were replayed offline against candidate house sets: same 3-minute 17-planet format, 2 maps × both sides, `node scripts/agent-value/league.mjs docs/agent-value/league-2026-11-26/timelines.json <sets> 2`. Score is the agent's wins + ½ draws (80 matches per set).

| House set | Agent score |
|---|---|
| `cautious` (Easy) | 0.68 (first run, 17 timelines × 4 maps) |
| `flanker` | 0.41 |
| `blob` (old Normal) | 0.31 |

`flanker` scored best of the sets that keep Easy < Normal < Hard (`blob` beats `flanker` 0.69, `pincer` beats `blob` 0.63, `RESULTS.md`), so it shipped first.
